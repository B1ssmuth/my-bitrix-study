# Автоматизация сервисного центра на Битрикс24

Прототип автоматизации процессов автосервиса, разработанный на базе корпоративного портала Битрикс24. Проект решает проблемы потери заказ-нарядов, обеспечивает прозрачность поставок запчастей и ведет структурированную историю обслуживания клиентских автомобилей.

## 1. Краткое описание архитектуры
Проект спроектирован с упором на современные стандарты разработки Bitrix Framework (D7 API), принцип инкапсуляции и строгое соответствие стандарту PSR-12. Весь кастомный код изолирован в директории `local/App/`.

* **Автозагрузка классов:** Реализована через `local/App/autoload.php`, что исключает использование устаревших конструкций `CModule::IncludeModule` для собственных классов.
* **Роутинг событий:** Все подписки на системные события вынесены в единый реестр `local/php_interface/events.php`. Логика обработчиков изолирована в ООП-классах внутри `local/App/Events/`.
* **Локализация:** Пользовательские тексты и названия полей выводятся через языковые файлы (`Loc::getMessage()`).

## 2. Используемые сущности и хранение данных
Для реализации функционала «Гараж клиента» применена архитектура на базе DataMapper (D7 ORM).

* **Модель данных:** Создана кастомная таблица `app_client_cars` и класс `\App\Models\Lists\CarsTable`. Этот подход обеспечивает нативную поддержку кэширования ядра и готовность сущности к REST-интеграциям.
* **Связи:** Настроено поле типа `Reference` для жесткой реляционной связи автомобилей с таблицей Контактов CRM (`\Bitrix\Crm\ContactTable`).
* **Пользовательский интерфейс:** Разработан компонент `otus:cars.grid` на базе `\Bitrix\Main\UI\Grid`. Через AJAX-слайдер динамически подгружается история сделок (заказ-нарядов), отфильтрованная по конкретному автомобилю.

## 3. Интеграции и работа с каталогом (Запчасти)
Автоматизирован контроль складских остатков с обращением к внешнему сервису.

* **Агент синхронизации:** Класс `\App\Agents\CatalogSyncAgent`, выполняющийся по расписанию (CRON).
* **Взаимодействие по сети:** Обращение к внешнему API (`random.org`) реализовано через нативный класс `\Bitrix\Main\Web\HttpClient`.
* **Учет остатков:** При выявлении нулевого остатка агент обновляет данные через D7 API каталога (`TYPE => 1`), автоматически генерирует заявку на закупку в Универсальных списках и отправляет push-уведомление ответственному закупщику через `\CIMNotify::Add`.

## 4. Бизнес-процессы (Заявки в отдел закупок)
Для ручного запроса запчастей механиками настроен Универсальный список с последовательным бизнес-процессом.

* **Архитектура:** Поле «Запчасть» реализовано как «Привязка к элементам CRM (Товары)», что исключает ошибки ручного ввода.
* **Защищенное обновление:** Начисление остатков на склад при одобрении заявки вынесено в изолированный кубик «PHP-код», который извлекает ID товара и корректно обновляет системную таблицу `b_catalog_product`.
* **Маршрутизация уведомлений:** При отказе автор получает точную причину, извлеченную из дополнительных переменных кубика «Утверждение документа».

## 5. Технические нюансы
* **Контроль незакрытых заказов (События):** Реализован обработчик `OnBeforeCrmDealAdd` (`\App\Events\GarageDealHandlers::checkOpenDeals`). Перед сохранением новой сделки система проверяет наличие ремонтов на нефинальных стадиях по выбранному автомобилю и при их обнаружении выбрасывает исключение, блокируя создание дубликата.
* **Кастомное логирование:** Стандартный обработчик исключений переопределен в `.settings_extra.php`. Подключен собственный логгер `\App\Debug\Log`, наследующий `FileExceptionHandlerLog`. Форматирование критических ошибок дополнено префиксом `[OTUS]` для удобной отладки.
